# Validation

Verified on Linux with OpenJDK 21.0.13 and JavaFX 21.0.6 under Xvfb.

- Seven JUnit tests pass, with zero failures/errors/skips.
- One parity test compares 660 native Java assessments against expected output
  generated by the uploaded application's original `engine.js`. Values, baselines,
  levels, result keys, trends, remeasurement flags, repeated-reading counts, and
  due flags match (floating-point comparison tolerance 1e-9).
- Boundary thresholds, fallback baselines, and correction/confirmation of a sudden
  glucose spike are tested separately.
- Persistent saves/reload preserve same-day history; invalid batches do not write,
  write errors preserve memory state, and malformed existing files are not reset.
- Reads remain available while an external persistence adapter is blocked.
- The GUI smoke run passes: 11 actual metric buttons, card/detail selection,
  historical repeated readings, invalid input feedback, inline scale entry,
  asynchronous save and repeat, reloading disk data, equipment-guide recording,
  saving for today while viewing a historical day, timer start/tick/close cleanup,
  and responsive layout from seven columns to fewer columns at 880 px.
- The supplied FXML wrapper loads in a separate JavaFX Stage during the UI test.
- A separate named-module JavaFX host loads the compiled component JAR, catalog
  through Gson, FXML controller, empty-data page, and nine-system level callback.
- Wide and narrow PNG previews are captured from the native JavaFX page.

The graphical check drives actual JavaFX controls with their actions. It is not
an OS-level mouse/keyboard automation test. Windows/macOS have not been executed
here; their JavaFX natives are selected by Maven. Native widget and font rendering
can vary slightly between platforms.

The source app's daily-metric assessment is reproduced, not its lab-panel/crew
comparison engine or the rest of the dashboard outside the supplied screenshot.
The included readings are the original SIM-1 invented demonstration data.

Run `mvn test` and `mvn javafx:run -Djavafx.args=--smoke` to repeat the checks.
The UI smoke run creates its own temporary reading store on every invocation.
